How It Works

Three steps from a description to a contract you deploy yourself

1

Describe

Write what the contract should do as structured pseudocode, or bring Solidity or Vyper source. Include the roles, the payment flows and the rules it has to enforce.

2

Convert

Send it to POST /api/v1/contracts/convert with the gateway's API key, or ask Trinity in chat. The answer carries the generated Solidity, Glasswing's report on it and the conversion's tier quote.

3

Deploy

Read the contract and the report, then deploy it with your own wallet. The gateway's deploy route answers 501, and conversion deploys only when an operator turns on conversion.auto_deploy.

What a Conversion Returns

One pipeline, the same for every request

There are no conversion plans. A conversion returns the generated Solidity and the name of the contract in it, the Glasswing report on that source (the same automated scan the audit page describes), the complexity tier with its fee quote (0.01, 0.05 or 0.1 ETH, or "negotiated" past a complexity score of 200; nothing collects it), and, when the source reads as a creative work, which template it started from. When blockchain.platform_wallet is set, the generated contract also carries the platform fee described under Fees in docs/blockchain.md. Nothing on this gateway takes an order or a payment for a conversion.

Request a Conversion

Ordering through this page is not live. The gateway has no endpoint that takes a conversion request or a payment, so this form sends nothing. The conversion pipeline itself is an authenticated API call: POST /api/v1/contracts/convert with the gateway's API key.
