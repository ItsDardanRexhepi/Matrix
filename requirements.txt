# 0pnMatrx — Runtime Dependencies (the lock)
# Install: pip install -r requirements.txt
#
# EXACT pins, and the whole runtime closure — not just the packages the code
# names. This is what the production image (Dockerfile), install.sh, setup.py
# and CI install, so it is the set a green suite describes. Every entry used to
# be an unbounded `>=`, which meant a future major of web3, eth-account,
# aiohttp or cryptography — or of eth-keys / hexbytes beneath them, which are
# in the signing path too — entered the image on its next build, unreviewed.
#
# pyproject.toml [project].dependencies carries the compatible RANGE for
# `pip install .`; this file carries the one tested point inside it.
# tests/test_dependency_manifests.py derives the needed set from the code's
# imports and the closure from installed metadata, and fails if the two files
# disagree, if anything here floats, or if the suite is not running on exactly
# these versions. To bump: install the new version, fix what breaks, update
# both files in the same change.
#
# Resolved for CPython 3.11 (the image and CI). A marker-conditional dependency
# that only applies to another interpreter (e.g. a backport on 3.10) is not
# locked here and would resolve freely there.
